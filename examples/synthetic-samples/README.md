# Sample-level pathway activity results

The Turtle that `kg/synthetic/` actually loads, cut down to something you can
read in one sitting. It answers:

> For this sample, which pathways are altered, in which direction, and measured
> against what?

Its sibling **synthetic-contrasts/** answers the *group*-level version of the
same question. The two are worth reading side by side: they are the same biology
at two granularities, and the difference in shape is the whole reason both exist.

## Contents

| File | Purpose |
|---|---|
| **data.ttl** | 4 samples and 11 results, extracted from a real pipeline run |
| **sample-to-pathway.rq** | Every result with its direction, z score and reference group |
| **validate.py** | Parses, checks the invariants — including two absences — and runs the query |

```bash
python examples/synthetic-samples/validate.py
```

## This file is generated, not written

```bash
python -m kg.synthetic.make_example          # regenerate
python -m kg.synthetic.make_example --check  # fail if stale
```

`data.ttl` is a **subgraph of the real output**, and the generator asserts it:
every triple emitted is checked for presence in the full 45k-triple run, blank
nodes matched by their property stars rather than by label. So "this is what
would be loaded" is a verified claim rather than a promise, and the excerpt
cannot describe a version of the pipeline that no longer exists.

`kg/synthetic/pipeline.py` regenerates it as its last step, so a pipeline change
that alters the output shape shows up here as a diff in the same commit.

## Representation

**The cohort spine uses the production model.** `sagebrain:has_sample`,
`sagebrain:has_diagnosis`, `sagebrain:source_tissue`, `sagebrain:Case` and
`sagebrain:Control` are all defined in `ontology/main/sagebrain.ttl` and
constrained by the shapes. This is the significant difference from
**synthetic-contrasts/**, which had to invent a `synv:` vocabulary for
everything: at sample level the model already says most of what is needed.

**The statistics are minted.** `sbkg:` terms — `scoring_method`,
`reference_group`, `expression_unit`, `gene_universe_digest`, `z_threshold` —
have no model equivalent yet. They live in a separate namespace so "the model
says this" and "an ingest needed this" are never confused at a glance;
`kg/schema/expression.yaml` is the proposal for promoting them.

**Every result is stated twice, on purpose.**

- `sagebrain:has_altered_activity_in` on the sample — a plain edge, for traversal.
- A reified `biolink:StudyResult` — carrying the direction, `biolink:z_score`,
  both p-values, and `prov:wasGeneratedBy` to the analysis.

The plain edge cannot say *down*, which is the single most useful fact about a
differential result, so the direction lives on the result as a real Biolink
predicate (`positively_correlated_with` / `negatively_correlated_with`). Two
representations of one fact can drift, so `validate.py` asserts they agree
exactly — that check is what makes the traversal edge worth having.

**Pathway nodes are referenced, never defined.** They belong to the Reactome
graph and are minted by `kg/reactome/`. `validate.py` loads
`data/reactome/v97/ttl/pathways.ttl` alongside to resolve labels; running the
query against `data.ttl` alone returns zero rows, and that is correct rather
than broken. Copying the pathway nodes in here would turn a reference into a
fork that stops tracking Reactome releases.

## What the 11 results say

| Pathway | AD | ALS | Reading |
|---|---|---|---|
| TLR4 Cascade | up | up | shared, positive |
| Transmission across Chemical Synapses | down | down | shared, negative |
| Regulation of cholesterol biosynthesis by SREBP | down | — | replicated in both AD cohorts, **not** shared |
| Fatty acid metabolism | down | **up** | discordant: altered in both, shared in neither |
| Mitochondrial translation | — | — | the batch decoy, **absent** |

Two of those rows are absences, and they carry as much of the argument as the
present ones:

- **The decoy has no results.** Grep for `R-HSA-5368287` and find nothing. It
  carries a library-chemistry offset applied to cases *and* controls alike, so
  standardising each sample against its own study's controls removes it exactly
  and nothing is materialised. A naive comparison of raw scores across cohorts
  would have called it shared biology in two different diseases.
- **The control sample has a node and no results.** It is the reference group the
  other samples' z scores are measured against. A file showing only samples with
  edges would imply the reference was missing from the data.

`validate.py` asserts both, because a check written only over what is present
would pass on a file where either had silently disappeared.

## Synthetic

Every participant, sample, score and p-value here was generated by
`kg/synthetic/simulate_counts.py` from a negative-binomial model with planted
effects. Nothing was observed. All fixture-owned IRIs contain
`/synthetic/`, and the analysis nodes carry `sbkg:synthetic true`.

The MONDO, UBERON and Reactome identifiers are real, and were resolved against
OLS4 and the Reactome graph rather than recalled.
